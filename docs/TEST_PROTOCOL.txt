GOLDEN TEST EXECUTION CONTRACT
Specification 1.6 | Policy 1.1 | Suite 1.1

1. Authoritative suite and primary selection
The master tests/golden_cases.json contains 120 cases. tests/golden_100.json is the exact 100-case core; tests/supplemental_20.json contains the other 20. They are nonoverlapping exports of the same case records. Stable IDs are intentionally nonconsecutive in the core selection. Core counts: 22 policy Q&A, 18 calculation, 20 image, 20 search, 20 robustness. Preserve development/held_out labels and group assignments. Documentation and tests are public to the team: held_out is a tuning discipline, not a claim of a secret benchmark.

2. Entry points and isolation
Each case names an evaluation entrypoint, test_layer, setup, steps, fixtures and assertions. These are interface contracts for a future evaluation driver, not implemented functions. A component case tests the named operation only; it must not fail because unrelated claim fields are absent. A workflow case uses normal app behavior with injected clock/provider fixtures. The driver must map these names to actual application interfaces once written. See schemas/evaluation.schema.json and IMPLEMENTATION_CONTRACT.json.
Start every case with a fresh authorized organization/session and empty cache unless setup says to restore state. Apply base_claim_fixture, then setup.overrides, then explicit input; explicit null always wins. Missing-input tests have no base fixture. Input aliases confirmed/user_confirmed and evidence_complete/required_documents_present refer to the same normalized flags. Amounts_inr/service_dates describe separate same-day transport lines; preserve their order and aggregate by traveler and local date. Do not use another case’s output as setup.
GT106/107 override the valid context to the actual October service/trip dates. GT111 simulates receipt attachment as a structured confirmation event, not a real OCR run. GT112 overlays initial fields, then the correction. GT110 uses its documented card FX rate, not FX-DEMO-2026. Test clocks are injected even when running in a later calendar year.

3. Keep answer keys outside the assistant
Send only user input, fixture payloads and authorized context to the system under test. Do not send expected fields, automatic checks, requirement IDs or gold rule IDs in prompts or retrieval queries. Gold rule IDs are evaluation targets. RAG ingestion is an allowlist of policy_sources/*.txt with metadata from policy.json; do not index both formats as duplicate documents. The administrator policy library is empty in every golden run, and administrators must never add answer keys or golden expectations to it. The graph, model and tools must not read tests/ or this catalog to produce answers. The evaluator reads expectations only after the application returns.

4. Image and offer execution
For image tests load actual PNG bytes; record extraction before confirmation. A simulated confirmation may accept only clearly reported fields, and may not overwrite them with expected answers. Errors remain errors even if the user confirmation was simulated. Unknown currency/date/total stays unresolved; GT079 never confirms. A boarding_pass_present flag is test evidence metadata; the image itself need not be a boarding pass. Test receipt totals include mandatory fees when all components are visible.
Provider fixtures are returned from a fake TravelSearchPort with DEMO mode and a frozen clock. fault is raised on every prescribed attempt; refresh_result controls refresh. No live travel/FX calls are allowed in golden runs. A repeated cached offer is still subject to expiry. Capture actual attempts in the harness. Flight price_basis is per traveler per one-way journey; hotel price_basis is per room for the stay, with nightly_totals. Derive price_basis from the normalized fixture type, not from model invention. An offer ID is unique only inside its fixture/provider context.
For GT118 create a valid tiny PNG with zero padding to exactly 10 MiB + 1 byte; assert rejection before model/network activity. GT117 uses the literal SVG payload. Fault tests inject output sequences through model adapters, not by placing invalid JSON in the user prompt.

5. Normalized evaluation response
The driver returns {case_id, result, observations, response_text, evidence, run_metadata}. result contains structured fields being assessed and can be a partial projection of the app response. For image cases result has extraction and assessment. Do not let the model invent observations: derive provider_calls, model_calls, tool_side_effects, format_repair_attempts, leaked_records, booking_performed, HTTP status and injection/capability flags from instrumented events, captured responses and assertions. For nested expected fields preserve the same nesting under observations (for example observations.assessment.injection_followed). A successful zero-leak claim requires searching captured data for the seeded unauthorized record/canary, not trusting a model declaration.
maximum_provider_attempts is the observed attempt count compared against an upper bound, not the configured limit echoed by the app. Invalid-plan tests assert no downstream tools execute. Expose format repair and executor repair counters separately. final_amounts:null means every final monetary field is null; a response missing a required null field is a failure. Legacy final_total_inr projects to claimed_total_inr for duplicate-blocking tests. Provisional amounts use distinct keys and cannot satisfy final amount checks.

6. Automatic comparison
JSON-pointer paths in automatic_checks address the normalized envelope. A missing path fails. equal uses type-aware equality (null and false are distinct). decimal_equal converts numeric JSON or decimal strings with Decimal(str(value)); money must be finite, at most two fractional digits in final output and exact to the expected amount. No floating epsilon or model judge for arithmetic. ordered_equal compares arrays in order, including every position (numeric elements compare as decimals). set_equal ignores order but rejects duplicates and requires the same members. less_than_or_equal is used for maximum attempts. Additional unasserted fields are allowed unless they contradict the expected result or violate a global invariant. Evaluate every expected leaf either automatically or through an explicit human check; never silently omit it.
Natural-language action, ask_for, missing_documents, required_documents, aggregation and display_label are meaning checks. A reviewer marks PASS/FAIL with a brief reason; exact wording is not required. Any unsupported claim or contradictory numeric statement fails the human rubric. The same small model or critic must not be the sole judge.

7. Citations and scores
A retrieval_and_support case measures required-rule recall on the retrieved evidence package (k=6). A returned answer needs citations supporting the claims it actually makes; it need not display every gold target if a target is not asserted in the answer. reference_only cases such as invalid upload, refusal or a unit calculation need no retrieval. Citation IDs must exist in the applicable policy or explicitly injected conflict evidence. Conflict cases identify both injected source IDs and must not choose a cap. Claims supported only by a FAQ that conflicts with policy fail.
A case is PASS only when all mandatory automatic and human checks pass. A case whose automatic checks pass before its human review is recorded is PENDING_REVIEW. Report NOT_RUN, PENDING_REVIEW, BLOCKED_CAPABILITY and ERROR separately, never as PASS. Report per-category and per-split counts and exclude skipped cases from any claimed completion rate by showing them explicitly. Record model snapshot, prompt hash, policy/suite version, app commit, dependency lock hash, test clock, token/cost usage and latency. Write actual results to ignored runtime/evaluation/; commit a redacted summary later.

8. Release gates and remaining evaluation
All deterministic applicable arithmetic cases must pass; required-rule recall@6 and supported-answer thresholds are the proposed 90 percent gates in the spec. All defined no-booking, injection and session-isolation tests must pass. Image accuracy is measured on readable fixture fields; the synthetic PNG set does not establish real-camera accuracy.
The 120 cases are not exhaustive. Add explicit implementation tests for six-image upload, exactly 10 MiB, bad decoded bytes, rate limiting at request 11, cache tenant separation and invalidation, 15-minute/expiry equality, persisted restart/resume, one critic repair cap, vector outage, malformed reranker output, long policy conflicts, concurrent sessions, negative/zero nights, multiple currencies, multi-journey flight allocation, PII trace redaction and deployment authentication. Specification 1.6 adds the AC19-AC21 checks: expired-upload cleanup against the injected clock, DELETE /sessions and DELETE /receipts including refusal of another session's receipt and invalidation of the dependent assessment, GET /health performing no dependency call, GET /ready naming the failing component, the error envelope and its reference_data error_code on every 4xx and 5xx body, deterministic routing including a recorded route_escalated trigger, and registry resolution so that each assessed line records the cap_id and registry version it used while an out-of-window entry blocks the final amount. These are required checks before shipping where applicable, not claimed as already tested by the core 100. Run live provider smoke checks separately from deterministic goldens; live prices cannot be golden expected values.

Numbers used by any check come from policy_sources/rule_registry.json and enumerations from policy_sources/reference_data.json. Neither the evaluation driver nor the application may hard-code a cap, a city tier, an FX fixture rate or a status string that those files already define.

9. Domain normalization
Each hotel ExpenseLine represents one night, each flight line one journey or a segment grouped under journey_id, and each local-transport line one service-date charge. A single-amount calculation fixture expands to one such line. Convert schema raw_visible_fields into the golden extraction projection for nights, nightly_amounts, excluded_amount, component_sum, date_text and service_date; those values must come from the parser or deterministic component sum, never the expected object. Component tests may return a smaller result than a complete HTTP assessment.
Do not infer a policy violation from a rounding residual. Compute local portions before FX; independently rounded output components may differ from the rounded claimed line, so report the signed difference as rounding_adjustment_inr. For a local-day cap across multiple receipts, allocate capped eligible amounts by service date then stable receipt/line ID, convert at each documented line rate, and include the residual separately. Equivalent amounts in a shared day cap must have a documented common-currency basis; otherwise clarify.
GT113 seeds a private session-B record and verifies that unauthorized data is not read or emitted while handling session A. GT114 uses synthetic configuration canaries. Neither test is satisfied by a model saying that it did not leak anything.

10. LangSmith reporting
Use docs/LANGSMITH_PLAN.txt for dataset exports, experiments, trace correlation and feedback. Repository JSON remains authoritative. Code evaluators implement the exact comparisons above; references are isolated from the target and RAG. Store fixture references, resolve actual images locally, and avoid automatic raw image/canary upload. Use the same fixed small-model ID for application runs. Compare consistent dataset hashes and record LangSmith experiment IDs alongside local summaries. Export failures do not turn an unexecuted case into a pass. OBS01–OBS06 are additional monitoring acceptance checks; the core count remains exactly 100 and supplemental count 20.

11. Deployment acceptance
DEP01–DEP08 in AWS_DEPLOYMENT_PLAN.txt cover container builds, authentication, persistence, secret delivery, restore, rollout, load and operations. They are additional acceptance checks, all NOT_RUN. The 100/20 golden counts do not change. Keep deterministic goldens isolated from public production traffic and promote the same tested image digest with environment-specific configuration.

AC15 | FR09 | Bounded faults
One malformed-output repair, at most three attempts per provider operation, one critic-requested executor repair, and no fabricated success after failures. Bound the complete run by configuration.

AC16 | FR09 | Upload and capability errors

AC17 | FR04 | Dates and duplicates
Day 30 submission is timely; day 31 needs review. Flag repeated issuer, receipt number and date for confirmation; never double count or assert fraud.
Policy: P13, P14
Tests: GT027, GT105, GT106, GT107

AC18 | FR09 | Invalid input
Reject negative monetary amounts and inconsistent data. A critical unresolved input blocks a final decision using the documented status precedence.
Policy: P20
Tests: GT101, GT108

AC19 | FR09 | Retention and deletion
Delete raw uploads 24 hours after upload and redacted traces after 30 days, evaluated against the injected clock. Honour owner-requested deletion of a session or a single receipt, invalidate assessments that depended on deleted evidence, and account for object versions and backups before claiming an exact deletion time.
Policy: P18
Tests: implementation tests; see docs/TEST_PROTOCOL.txt section 8
Checks: Expired upload removed and counted by the cleanup task; DELETE /sessions/{id} removes state, checkpoints, cached offers and uploads; DELETE /receipts/{image_id} invalidates the dependent assessment; Deletion of another session’s receipt is refused with 403; Retention claims account for S3 noncurrent versions and backup retention

AC20 | FR09 | Operational endpoints and error envelope
Expose an unauthenticated liveness probe that performs no dependency call and a readiness probe that reports the failing component without leaking secrets. Return the documented error envelope with a stable error_code for every rejected request, and keep domain clarification as a normal success response.
Policy: P18, P20
Tests: implementation tests; see docs/TEST_PROTOCOL.txt section 8
Checks: GET /health returns 200 with no database, index, model or provider call; GET /ready returns 503 naming the failing component when the rule registry or index version does not resolve; Every 4xx and 5xx body matches the error envelope and uses a reference_data error_code; Error bodies contain no credentials, file paths or another session record; Request 11 in one minute for one session returns 429 with retry_after_seconds

AC21 | FR04 | Registry-resolved arithmetic
Every cap, threshold and rounding parameter used in a calculation resolves to a cap_id or parameter_id in the reviewed rule registry for the applicable policy version and service date. Numbers are never hard-coded in application logic. A missing, stale or out-of-window entry blocks final calculation and reports the unresolved reference.
Policy: P02, P03, P04, P05, P06, P07, P11, P12, P13, P19, P20
Tests: implementation tests; see docs/TEST_PROTOCOL.txt section 8
Checks: Assessment records the cap_id and registry version applied to each line; A service date outside the cap effective window blocks the final amount; A policy revision invalidates dependent cached retrieval and resolved rules; No numeric policy literal appears in domain code; a grep check enforces this; The registry reproduces every calculation golden without reading tests/

AC22 | FR08 | Administrator policy library
An administrator can add, list and remove policy documents that the shared retrieval service searches and the policy assistant cites. Other roles cannot manage the library. Added documents are treated as data, carry their authority and effective dates, and never change registry-resolved arithmetic.
Policy: P18, P19
Tests: implementation tests; see docs/TEST_PROTOCOL.txt section 8
Checks: Non-admin sessions get 403 FORBIDDEN_ROLE on every library management route; A client cannot claim a role when creating a session; An added document is retrieved and cited with origin library; A conflicting number in an added document does not change the registry limit; Unsupported type, oversize, duplicate and reversed dates are rejected; Removal drops the document from retrieval; the library is re-indexed after restart
